# ТЗ: Система «Услуги мастеров» — поэтапная реализация

Статус: Этап 1 ✅ · Этап 2 ⏳ · Этап 3 ✅ (без публикации) · Этапы 4–6 ⬜

## Схема данных

| Сущность | Где | Ключевые поля |
|---|---|---|
| Анкета мастера | Supabase `orders` (песочница) | `service_name='Анкета мастера'`, `metadata.domain='master'`, `metadata.description` = специализация · опыт · город · о себе, `metadata.photo`, `status='review'` |
| Услуга мастера | Supabase `master_services` (service-key в монолите) | `master_id, master_name, title, description, price (число), price_variants (текст «с сушкой 2 000 / без 1 500»), photos[], phone, status: pending\|approved\|rejected\|paused` |
| Каталог услуг | монолит `/api/catalog-services` (Supabase storage services.json) | 46 услуг wash/build/frame/move/rent (+ garden — добавить в DEFAULT_SERVICES) |

Адреса: песочница `https://broverse-client.vercel.app`, монолит `https://broverse-masters.vercel.app`.

## Этап 2 — «Мои услуги» в кабинете мастера ⏳ (в работе)

**Код:** монолит `app/page.tsx` → `MasterServicesSection` (Профиль).

**Функция:**
1. Кнопка «Добавить услугу» → выбор из каталога `/api/catalog-services`:
   - домены мастера (для master-1 = wash) — кликабельны;
   - чужие домены — под замком 🔒 «По приглашению»;
   - garden — локальный список 3 услуг (нет в каталоге).
2. Для выбранной услуги: цена (число), варианты цен (текст), фото, описание → POST `/api/master-services` → `status='pending'`, чип «На модерации».
3. Тумблер вкл/выкл: approved ⇄ paused (PATCH status). paused = «Приостановлено» (не получает заказы).
4. Существующее: редактирование цены кликом, удаление, чипы статусов.

**Проверки:**
1. `npx tsc --noEmit` (в монолите).
2. В мастерах → Профиль → «Мои услуги»: «+» открывает каталог; чужой домен заблокирован; услуга сохраняется со статусом «На модерации».
3. `curl -s 'https://broverse-masters.vercel.app/api/master-services?master_id=master-1'` → запись с price/price_variants/status=pending.
4. Тумблер: PATCH status=paused → в списке чип «Приостановлено»; обратно — «Одобрено».

## Этап 4 — Объявления мастеров на клиентском сайте ⬜
1. Одобренная услуга (`status=approved`) + профиль мастера = карточка-объявление: фото мастера, имя, описание, фото услуги, цена, рейтинг.
2. Раздел «Мастера» на главной хаба (секция/страница `/masters`).
3. API: `GET /api/masters/ads` (песочница, server-side → Supabase anon на `master_services` где approved, + master-профиль).
4. Привязка к справочнику каталога: цвет/бренд/категория из catalog по названию/domain → актуальность каталога.

**Проверки:** на главной отображается одобренная услуга мастерa; карточка открывается; неодобренная — не видна.

## Этап 5 — Поиск по объявлениям ⬜
1. `SmartSearch`: дополнительно к INTENT_MAP/каталогу — fetch одобренных объявлений.
2. Выдача: «Мастера: Евгений — Химчистка дивана — 2 000 ₽» с переходом в раздел «Мастера».

**Проверки:** запрос «химчистка» → в результатах объявление мастера; запрос без совпадений каталога, но с совпадением у мастера — тоже находится.

## Этап 6 — Фильтр карты заказов + предложения (апсейл) ⬜
1. Карта заказов мастера: переключатель «Все / Только мои услуги» — фильтр по активным услугам (approved, не paused).
2. `service_offers`: матрица предложений (wash→rent, move→garden, build→rent…); баннер-предложение в кабинете; согласие → услуга в «Мои услуги» pending.
3. Уведомления: in-app баннер; Telegram через @BroVerse_Masters_Bot (masters-webhook) — если chat_id привязан.

**Проверки:** фильтр показывает только заказы по включённым услугам; предложение отображается и принимается; после согласия услуга появляется в «Мои услуги» на модерации.

## Ограничения / известное
- `master_services` без авторизации (service-key только в монолите) — публичный read для хаба сделать через anon-RLS или server-proxy (этап 4).
- `price_variants` — новая колонка: если в Supabase её нет, PATCH/POST вернёт ошибку — создать колонку (text) в SQL-редакторе Supabase.
- master_id='master-1' захардкожен (демо-кабинет без auth) — при появлении auth заменить на реальный id.
- Уведомления TG — позже (нужен chat_id мастера).
